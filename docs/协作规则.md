# 协作规则

两个人、三天、两台电脑。规则越少越好，但下面这几条不要破。

## 每天的核心循环

1. 开工先点 `Fetch origin`，有更新就 `Pull origin`
2. 干活，改自己的文件
3. 做完一小块就 `Commit to main` + `Push origin`
4. 收工前再推一次

不要攒到晚上一起提交。攒一天的结果是出问题时不知道是哪一步坏的。

## 三条硬规矩

1. **只改自己负责的文件。** 文件分工看 `README.md` 里的表格。
2. **推之前自己跑一遍。** 浏览器里打开游戏，确认没白屏、没报错。
3. **大文件不进仓库。** 视频、录屏、几十兆的原图放共享网盘，仓库只放代码和小图。

## 文件分工

- 甲：`index.html`、`src/game.js`
- 乙：`src/visuals.js`、`src/ui.js`、`src/styles.css`
- 共同：`assets/`、`docs/`

`index.html` 归甲。乙如果要往里加东西（比如新的 script 标签），先说一声。

`assets/` 里的文件名带自己名字缩写，比如 `a-zombie.png`、`b-gunshot.wav`，方便认。

## 提交说明怎么写

一句话说清做了什么，中文就行：

- 加了僵尸生成和追击
- 修了子弹打不中的问题
- 换成新的地面贴图
- 加了看广告复活弹窗

## 出问题怎么办

- **Push 被拒绝**：点 `Pull origin`，再 `Push origin`。
- **Pull 下来跑不起来**：看对方最后一次提交的说明，在 `History` 里找到那笔提交退回。
- **两个人改了同一行**：GitHub Desktop 会提示冲突。不要硬改，把两个文件发给 AI 合并，或者一个人手动选保留哪版。

## 每天的同步

- 中午一次，收工前一次，各 10 分钟
- 对齐三件事：做到哪了、卡在哪、下一步谁做什么
- 调试时直接开屏幕共享

## 一个必须遵守的时间点

第一天结束前，必须有一个能跑的版本推上去。三天项目最常见的死法是最后一天拼不起来。
