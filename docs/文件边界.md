# 文件边界

两个人各自做什么、能改什么，写在这里。把甲、乙换成你们的名字。

## 一句话分工

- **甲**：玩法。游戏怎么玩、数值多少、什么时候刷怪、什么时候结束。
- **乙**：画面。场景长什么样、模型和特效、界面怎么显示、素材怎么做。

## 谁负责哪些文件

| 文件 | 负责人 | 另一方 |
| --- | --- | --- |
| `index.html` | 甲 | 不要改，需要加东西先说 |
| `src/game.js` | 甲 | 不要改 |
| `src/visuals.js` | 乙 | 不要改 |
| `src/ui.js` | 乙 | 不要改 |
| `src/styles.css` | 乙 | 不要改 |
| `assets/` | 两人 | 只加自己的，不删不改对方的 |
| `docs/接口约定.md` | 两人 | 改数据结构前必须商量 |
| `docs/协作规则.md` | 两人 | 改之前说一声 |
| `.gitignore` | 甲 | 不要改 |

## 甲可以直接做

- 改玩法逻辑：移动、射击、碰撞、刷怪、波次、复活
- 改 `CONFIG` 里的所有数值
- 改 `index.html` 的结构
- 在 `assets/` 里放 `a-` 开头的素材

## 乙可以直接做

- 改 3D 场景、相机、灯光、模型、特效
- 改血条、分数、开始页、结束页
- 改界面样式
- 在 `assets/` 里放 `b-` 开头的素材
- 新建 `src/visuals-xxx.js` 或 `src/ui-xxx.js`，建之前说一句

## 两边都不要做

- 改对方负责的文件
- 改 `state` 的结构。要加字段先商量，由甲来加
- 改 `CONFIG` 里的数值。乙觉得手感不对，反馈给甲
- 删除或重命名对方放进 `assets/` 的文件
- 动 `.git/` 目录

## 必须商量的三件事

1. **接口变了**：`state` 加字段、事件改名、函数签名变了
2. **新建文件**：`src/` 下新增文件，或根目录新增文件夹
3. **改说明文档**：`README.md`、`docs/` 里的其他文件

商量之后两边同一天改完，不要一个人先改一边。

## 接口要变怎么走

比如乙想给僵尸加一个“朝向”字段：

1. 在群里说：加什么、为什么加
2. 甲在 `game.js` 里加，并更新 `docs/接口约定.md`
3. 乙在 `visuals.js` 里使用

不要自己在 `visuals.js` 里给 `state` 挂字段。那样刷新就没了，甲那边也不知道。

## 新增文件怎么命名

- `src/` 下：`visuals-xxx.js` 或 `ui-xxx.js`，一眼看出属于哪一层
- `assets/` 下：`a-` 或 `b-` 开头，比如 `a-ground.png`、`b-zombie.glb`
- 不要在仓库根目录新建文件夹

## 素材规则

- 单个文件不超过 5MB
- 视频、录屏、几十兆的原图不要进仓库，放共享网盘
- 3D 模型用 GLB，不要用 FBX 或 Blend
- 贴图用 PNG 或 WebP，尺寸不超过 2048
- 同一类素材先做两三个，确认风格统一再批量做

## 提交前检查

1. 只改了自己范围内的文件
2. 浏览器里跑过，没白屏、控制台没红字
3. 提交说明写清了这次改了什么
4. 没有把大文件带进仓库

## 拿不准的时候

先问，再动手。三天时间经不起返工，问一句的成本远低于两个人互相覆盖。
