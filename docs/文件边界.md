# 文件边界

这份文件规定两个人各自能改什么、不能改什么。核心只有一句：

**只改自己负责的文件，需要动对方的文件先说一声。**

甲负责玩法（`game.js`、`index.html`），乙负责画面（`visuals.js`、`ui.js`、`styles.css`）。下面以乙的视角写，甲反过来同理。

## 可以直接改，不用问

- `src/visuals.js`：3D 场景、相机、灯光、模型、特效
- `src/ui.js`：血条、分数、开始页、结束页
- `src/styles.css`：界面样式
- `assets/` 里自己新建的素材，文件名加 `b-` 前缀
- `docs/接口约定.md` 里关于画面层的说明，前提是不改数据格式

## 改之前要先说一声

- `index.html`：归甲。要加标签、改页面结构，先说
- `docs/接口约定.md` 里的数据结构和事件：两边都依赖，改一处要两边同时改
- 新建 `src/` 下的文件：可以建，但要在群里说一句，并且只从 `visuals.js` 或 `ui.js` 引入
- `README.md`：改之前说一声，避免两个人同时改同一段

## 不要动

- `src/game.js`：玩法逻辑、数值、状态，全是甲的
- `CONFIG` 里的任何数值：手感不对就反馈，不要自己改
- `state` 的结构：需要新字段就提需求，由甲来加
- `.gitignore`
- 别人放在 `assets/` 里的文件：不删、不改名
- `.git/` 目录：任何情况都不要手动动

## 新增文件怎么命名

- `src/` 下：`visuals-xxx.js` 或 `ui-xxx.js`，一眼看出属于哪一层
- `assets/` 下：`b-` 开头，比如 `b-zombie.glb`、`b-gunshot.wav`
- 不要在仓库根目录新建文件夹，除非先说

## 接口要变怎么办

如果确实需要在 state 里加东西（比如僵尸的朝向、受击闪白的剩余时间），按这个顺序：

1. 在群里说明加什么、为什么加
2. 甲在 `game.js` 里加字段，并更新 `docs/接口约定.md`
3. 乙在 `visuals.js` 里使用

不要自己在 `visuals.js` 里给 state 挂字段。那样刷新就没了，而且甲那边完全不知道。

## 素材规则

- 单个文件不超过 5MB
- 视频、录屏、几十兆的原图不要进仓库，放共享网盘
- 3D 模型用 GLB，不要用 FBX 或 Blend
- 贴图用 PNG 或 WebP，尺寸不超过 2048
- 同一类素材先做两三个，确认风格统一再批量做

## 提交前检查

1. 只改了自己范围内的文件
2. 浏览器里跑过，没白屏、控制台没红字
3. 提交说明写清了这次改了什么
4. 没有把大文件带进仓库

## 拿不准的时候

先问，再动手。三天时间经不起返工，问一句的成本远低于两个人互相覆盖。
