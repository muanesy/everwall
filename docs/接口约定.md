# 接口约定

两个人同时写代码，靠这份约定保证拼得起来。改动接口前先在群里说一声，两边一起改。

## 分工边界

- `src/game.js` 维护数据，负责改
- `src/visuals.js`、`src/ui.js` 只读数据，负责画
- 画面层不要直接改 `state` 里的任何字段

## 游戏状态 state

由 `game.js` 创建和维护，作为参数传给画面层。

```
state = {
  status: 'menu' | 'playing' | 'over',
  time: 本局已进行秒数,
  wave: 当前波次，从 1 开始,
  score: 分数,
  soldiers: 士兵数量。同时是生命值，归零就结束,

  player: {
    x: 左右位置（-8 到 8）,
    z: 纵深位置（固定 9）
  },

  bullets: [
    { id, x, z, vz, damage }
  ],

  barriers: [
    { id, x, z, value, maxValue, negative, speed }
  ],

  zombies: [
    { id, x, z, hp, speed, type, aggro }
  ]
}
```

## 坐标和分区

这是俯视角。`x` 是左右，`z` 是纵深（屏幕上下），`y` 是高度。

| 名字 | 值 | 含义 |
| --- | --- | --- |
| 玩家位置 | `z = 9` | 屏幕下方 |
| 出生位置 | `z = -26` | 屏幕上方之外 |
| 进入屏幕 | `z = -21.5` | 越过这条线，+1 屏障才能被打中 |
| 防线 | `z = 8.4` | 僵尸越过这里，士兵减员 |
| 左区 | `x` 在 -7.6 到 -0.6 | +1 屏障出现的地方 |
| 右区 | `x` 在 0.6 到 7.6 | 僵尸出现的地方 |

## 事件

`game.js` 用 `events.dispatchEvent(new CustomEvent(...))` 发出，`visuals.js` 监听。

| 事件名 | 触发时机 | detail |
| --- | --- | --- |
| `shoot` | 玩家开火 | `{ x, z }` |
| `barrierHit` | 子弹打中负数屏障一次 | `{ x, z, value }` |
| `barrierApply` | 屏障数值生效（达到上限或碰到士兵） | `{ x, z, value }` |
| `zombieDie` | 僵尸死亡 | `{ x, z, type }` |
| `armyHurt` | 僵尸碰到士兵或越过防线 | `{ soldiers, amount, cause }`，cause 是 `'touch'` 或 `'pass'` |
| `waveStart` | 进入新一波 | `{ wave }` |

新增事件时，两边都要改：`game.js` 里 emit，`visuals.js` 里 addEventListener。

## 画面层必须提供的函数

`game.js` 会调用这两个：

```
initVisuals(container, events)
  初始化场景。只调用一次。

syncScene(state, dt)
  每帧调用。dt 是距上一帧的秒数。
  负责把 state 画出来，并更新特效动画。
```

`ui.js` 必须提供：

```
initUI(state, actions)
  actions = { start, restart, revive }
  初始化界面。只调用一次。

updateUI(state)
  每帧调用。根据 state 更新士兵数、分数、显示哪一层界面。
```

## 几条规则

- 屏障在 `z < -21.5` 时不可被击中，哪怕子弹从它身上穿过
- 屏障从左边界一直铺到中间，一排排压下来
- 大部分屏障是 `+1`，一发子弹就碎，士兵 +1
- 少量屏障是负数，初始值在 -30 到 -10 之间，上限是 10 到 30
- 打中负数屏障一次，数值 +1；达到上限时数值生效，加对应数量的士兵
- 屏障碰到士兵时，当前数值立刻生效：正数加兵，负数扣兵
- 屏障从旁边越过去不生效
- 子弹是一束多发齐射，总宽度 0.9，发射点很集中
- 士兵数量影响射速和齐射发数：人越多打得越快、子弹越多
- 僵尸碰到士兵扣 1，越过防线扣 5
- 僵尸走到 `z > 5` 且离士兵 4 以内才开始横向追人，转向速度 3.5，追人后会一直被标记为 `aggro`
- 僵尸基础移动速度 3.2，每波还会加快
- 僵尸之间有 0.6 的最小间距，靠太近会互相推开，避免叠成一坨
- 一局开始时士兵是 5 个，复活后是 20 个

## 数值在哪改

全部在 `game.js` 顶部的 `CONFIG` 里。改完保存，Live Server 会自动刷新。

要点：

- `barrier.spawnInterval` 控制屏障压下来的密度
- `barrier.rowGap` 是同一排里屏障的横向间隔
- `barrier.negativeChance` 是负数屏障出现的概率
- `barrier.negativeMin` / `negativeMax` 是负数屏障的初始范围
- `barrier.capMin` / `capMax` 是负数屏障打满后的上限
- `player.volleySpread` 是齐射的横向总宽度，调小更集中
- `zombie.spawnInterval` 和 `intervalPerWave` 控制僵尸潮的强度
- `zombie.touchLoss` 是碰到士兵扣几个兵，`zombie.passLoss` 是越过去扣几个兵
- `zombie.turnSpeed` 是僵尸横向追人的速度，调小更容易甩掉
- `zombie.aggroStartZ` 和 `zombie.aggroRadius` 决定僵尸多近才开始追人
- `zombie.separation` 是僵尸之间的最小间距

调试：浏览器控制台输入 `__state` 可以看实时状态（士兵、僵尸、子弹数量）。

## 换成模型时改哪里

只在 `visuals.js` 里改：

- `playerMesh` 的创建（现在是方块）
- `makeBarrierMesh()`（绿色横条 + 浮动的 +1 标签）
- `makeZombieMesh()`（现在按 type 换颜色）
- 士兵是 `InstancedMesh`，最多同时画 60 个，超出的只体现在 HUD 数字上
- 如果要加载 GLB，用 `GLTFLoader`，导入路径是 `three/addons/loaders/GLTFLoader.js`

`game.js` 不需要知道模型长什么样。

## 断网兜底

`index.html` 里的 importmap 指向 jsdelivr 的 CDN。演示前如果担心断网：

1. 下载 three.js 到 `lib/` 文件夹
2. 把 importmap 里的地址改成本地相对路径
3. 断网测试一次

这一步放在最后一天做，不要提前折腾。
